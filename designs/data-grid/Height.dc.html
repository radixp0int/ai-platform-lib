Height

The table sets the height. The panel fills it and scrolls inside.

Today the docked panel is its own card with its own height, so the two bottoms almost never line up. In the DataGrid they share one frame. The panel can never make the row taller, and it can never stop short.

More filters than rows: the panel's list scrolls between its header and footer. A fade at the bottom says there is more. Header and footer bands line up with the table's.

One or two rows: the grid keeps a minimum body height (about 7 rows, 26rem) so the panel is still usable. The extra space belongs to the table and its footer stays at the bottom, so the page doesn't jump as results change.

How it works

1. One grid. grid-template-columns: 17rem 1fr on the frame. Grid rows stretch by default, so both columns are always the same height.

2. Panel can't push. Its field list is position: absolute; inset: 0; overflow-y: auto inside a flex cell. It takes no room, so only the table decides the height.

3. Narrow screens. Under 1024px the panel floats over the grid again (as it does unpinned today). There is no side-by-side height to match.
